# Operating Rhythm

## 目的
チーム運用を個人技にせず、週次と月次の確認を同じ型で回す。

## 使う場面

- `ops/weekly-review.md` を更新する時
- Phase 2 ゲート（Gate A / Gate B）の進捗を整理する時（`ops/milestone-tracker.md` を更新）
- 月次コストの要点をまとめる時

## 週次で見ること

- 今週進んだこと
- 止まっていること
- 意思決定が必要なこと
- 来週やること
- **Gate A / B 進捗のスナップショット**（`ops/milestone-tracker.md` の各観点を更新し、`ops/weekly-review.md` の冒頭ブロックにも転記）
  - **Gate A**: 累計本数 / トピック網羅（5系統） / 質的水準 / 構造 / 外形
  - **Gate B**: 機能完走性 / 9軸品質サイクル / AIキャスト評価 / パフォーマンス / 安定稼働 / コスト / モバイル

## 月次で見ること

- コストの増減
- モード逸脱の有無
- 成果指標の変化
- **Gate A / B の月次達成度判定**（`ops/milestone-tracker.md` の月次表に追記）
- **行き詰まり判定**: いずれかのゲートで2ヶ月以上進捗ゼロが続いていないか確認。発火していたら ディレクター ＋ マーケター ＋ レビュアー でゲート条件自体の妥当性を再評価
- 両ゲート達成時は **マーケター主導で Phase 3 マーケティング戦略実行に移行** する判断ログを起票

## 出力フォーマット

```md
## 定例まとめ

### 今回の対象期間
- ...

### 進んだこと
- ...

### 詰まり
- ...

### 要判断
- ...

### 次の打ち手
1. ...
2. ...
```

## 注意

- 事実と解釈を混ぜない
- 数字があるものは数字で書く
- 次アクションがない定例まとめにしない
