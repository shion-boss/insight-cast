## 採用方針

5項目を通して一貫させる軸は「**出典のある事実 + 世界観の温度 + 分かりやすさ**」の三角形を崩さないこと。

- TOP 5（proof 1行）は数字を持ち込むが、白書の文脈で出すことで「大げさな主張」にならない形を選ぶ
- TOP 6（引用置き換え）は OutputExample の塗装業の事例と同じ「当たり前の気づき」の瞬間を別業種で再現する。業種は意図的に別にして「業種を問わない」を示す
- TOP 7（Compare 前置き）は既存提案を精査し、Pattern A（Hermès letterhead）のトーンとの整合性を評価した上で採用可否を判断する
- TOP 8（Pricing catch）は「誰が選ぶか」の選択基準を立てることで、読み手の自己分類を促す。ただし現状も悪くないため、現状維持の選択肢も明示する
- TOP 10（CastTalk差別化）は「ブランドの舞台裏を覗く窓」として位置づけ直し、BlogPreview（実用記事）との役割分け を heading + 補足文で体現する

## TOP 5 — PainSection proof 1 行

### 現状

`PainSection.tsx` の構造:

```
eyebrow: PAIN
heading: やる気があっても、問いがなければ始まらない。
痛みリスト:
  ・何を書けばいいか分からない
  ・自分の強みが言葉にならない
  ・毎回ゼロから考えるのがたいへん
（proof なし）
締め: 問いさえあれば.... 答えられるのに。
```

痛みリストの後に出典付きの裏付けがない。主張だけが並んでいる状態。

### 提案候補

**A. 中小企業庁「中小企業白書」の情報発信調査から引く**

> 中小企業の約8割は、自社の強みを「まだ十分に発信できていない」と感じている。
> ——中小企業庁「中小企業白書 2023年版」

出典: 中小企業庁「2023年版 中小企業白書」第2部 第3章
URL参考: https://www.chusho.meti.go.jp/pamflet/hakusyo/2023/

注意: 上記の「約8割」という数字は白書の調査データから導いた数値感であり、白書に完全一致の表現があるとは限らない。実装前に原文を確認して正確な数値・引用箇所を確定すること。数字が白書で確認できない場合は候補Bまたは候補Cを採用する。

**B. 情報通信白書（総務省）のICT活用調査から引く**

> 中小企業のうち、Webサイトを「定期的に更新できている」と答えた割合は3割台にとどまる。
> ——総務省「情報通信白書 令和4年版」

出典: 総務省「令和4年版 情報通信白書」ICT活用動向調査
URL参考: https://www.soumu.go.jp/johotsusintokei/whitepaper/ja/r04/html/

注意: 候補Aと同様、実装前に原文で数値を確定すること。「3割台」という数値感は白書調査のトレンドに基づく推計であり、正確な引用文は原文参照後に確定する。

**C. 出典を特定せず、事実感を「現場の声」として表現する（数字なし版）**

> 「何を書けばいいか分からない」は、HP更新が止まった事業者の多くが口にする言葉です。

出典: なし（主張として提示。proof の代わりに「広く知られた現象の言語化」として機能させる）

### 採用推奨 → B（候補Bを実装前確認の上で採用。確認できなければA、それも確認できなければC）

**理由:**

1. 「Webサイトを定期的に更新できているか」という問い方が、ターゲット（HP更新が止まっている中小企業）の痛みに直結しており、読み手の「まさに自分だ」という共感を数字で補強できる
2. 総務省「情報通信白書」は公的出典として信頼性が高く、40-60代の読み手にも「お役所のデータ」として受け入れやすい
3. 候補Aの「強みを発信できていない」よりも、痛みリストの3項目（書けない・言語化できない・ゼロから考える）に対するより直接的な証拠になる
4. 候補Cは出典がないため proof としての機能が弱く、LP 構成原則「proof 要素が必要」を満たさない

**実装前タスク（エンジニアへ）:** 総務省 情報通信白書 令和4年版（または最新版）の原文で「中小企業 Webサイト 更新頻度」に関する数値を確認し、正確な引用表現と出典箇所を確定してから掲載すること。数字が見つからない場合は中小企業白書（候補A）を次の選択肢とする。

## TOP 6 — SolutionBridge 引用 → 実例に置き換え

### 現状

`SolutionBridge.tsx` の引用ボックス（右カラム）:

```
"あなたの「当たり前」の中に、
まだ伝わっていない強みがあります。
AIキャストが引き出して、記事にします。
```

これは主張であって proof ではない。概念を言葉にしているだけで、読み手に「本当にそんなことが起きるのか」という実感を与えられていない。

---

### 提案候補

**A. 塗装業の事例（OutputExample との整合版）**

OutputExample で使われている塗装業の事例と同じ事業者の「気づき」の瞬間を引用形式で再現する。

> 「父の代からずっとやってきたことなんですが、取材で話すまで、それがアピールポイントだとは思っていませんでした。」
>
> ——外壁塗装業　50代 代表者　取材より

LP内で塗装業の事例を2回参照することになるが、OutputExampleとは「会話」と「気づきの言葉」で異なる形で見せるため、重複感は生じにくい。

**B. 別業種（整骨院）の事例**

OutputExample（塗装業）との重複を避け、別業種で「当たり前の気づき」の瞬間を作る。

> 「毎回、患者さんの名前と前回の状態をメモしておくのは当然だと思っていました。でも取材で話してみたら、それを続けている院はほとんどないと言われて。」
>
> ——整骨院　40代 院長　取材より

「業種を問わず機能する」という Insight Cast の汎用性を示すために、あえて塗装業以外の業種を使う。

**C. 業種を特定しない「会話の断片」**

業種を出さずに「気づきの瞬間」だけを切り取る。

> 「『当たり前のことですから』と話しかけたとき——
> そこに、まだ誰にも伝わっていない強みがありました。」

これは実例感より「詩的な余韻」に寄るアプローチ。Hermès letterhead トーンとは合うが、proof としての機能は弱くなる。

---

### 採用推奨 → B（別業種・整骨院）

**理由:**

1. LP内でOutputExample（塗装業）がすでに詳細な事例として機能している。SolutionBridgeで同じ塗装業を使うと「同じ業種しか対応していない?」という誤読リスクがある
2. 整骨院の事例は「患者の名前と前回の状態をメモする」という行為が、40-60代の地域中小企業主に身近で理解しやすい
3. 「毎回メモする → 当然だと思っていた → でも実はやっていない院が多い」という構造が、OutputExampleの塗装業事例と同じ「当たり前の気づき」のパターンを別業種で実証している。「どの業種でも同じことが起きる」を読み手が感じ取れる
4. 候補Cは proof として弱く、「主張から実例へ」という改善意図を満たさない

**取材ステータスについて:** 現時点（Phase 2 ドッグフーディング期）で整骨院の実取材はない。このコピーは「取材を想定したサンプル」として掲載し、文末に「※取材サンプル」の注釈を添える形が誠実。実顧客が出た時点で差し替える前提で使う。ただし「取材より」という表記を使う場合は実際の取材に基づくこと。表記を「事業者の声 イメージ」に変えるか、サンプルであることを括弧書きで添えるかは運営が判断する。

---

### 採用推奨の最終文面

引用ボックス内のテキストを以下に差し替える:

```
「毎回、患者さんの名前と前回の状態をメモしておくのは当然だと思っていました。
でも取材で話してみたら、それを続けている院はほとんどないと言われて。」

——整骨院 40代 院長
（取材サンプル）
```

引用部分は既存の引用ボックスのスタイル（`#f5e8d8` bg、serif体、大型引用符）をそのまま使用。末尾の `——` 以降の出典表記は 12px キャプションスケール。`（取材サンプル）` は 11px、`color: #a09080`（薄め）で控えめに出す。

**修正対象ファイル:** `app/(site)/_components/lp/SolutionBridge.tsx`

## TOP 7 — CompareCards 前置き 1 行

### 現状

`CompareCards.tsx` の見出し:

```

（前置き文なし）

3カード（忙しさで悩む方へ / 言語化で悩む方へ / 予算で悩む方へ）
```

3カードが「忙しさ」「言語化」「予算」と異なる切り口で並んでいるため、見出しだけでは「3つが何を共通として示しているか」が分かりにくい。

### 既存提案の評価（`docs/specs/copy-improvement-top-2026-04.md` 変更箇所1）

既存提案のテキスト:

> AIツールも、記事代行も、「すでに書く材料を持っている人」向けに作られています。
> Insight Cast はその前の段階——「何が自社の強みか、まだ言葉にできていない」という
> 根本から引き出すことが、仕事の核心です。

**評価:**

強みとして機能している点:
- 「A でも B でもなく C」の構造が明確。競合を名指しせずに差別化を示している
- 「すでに書く材料を持っている人」という言い方が、ターゲット（材料がない人）に正確に刺さる
- 「根本から引き出すことが仕事の核心」という一言が Insight Cast の本質を端的に表している
- 「材料」「根本」「引き出す」は 55歳の工務店社長が3秒で理解できる日常語

世界観整合チェック（Pattern A・Hermès letterhead 風トーン）:
- ビジネスライクすぎず、砕けすぎず、適切な距離感
- 「仕事の核心です」という言い方が少し硬いが、CompareCards のセクション（比較・論理提示の場）では許容範囲
- 「——」（ダッシュ）の使い方がやや記事寄り。LP の前置き文としては2文に分けた方がリズムがよい

文体（LP全体との統一感）:
- 現状 LP の他のセクション補足文のトーンは「使いやすいかどうかは、使ってみないと分かりません。」（Pricing）など、体言止めを使わず自然な語尾で締めている
- 既存提案の「仕事の核心です。」はこのトーンと合っている
- ただし `——（ダッシュ）+ 長い説明節` という文の構造が、他のセクションの補足文より複雑。簡潔化を推奨

**採用判断: 採用。ただし微調整を推奨。**

### 現状の評価

良い点:
- 「個人向け」と「法人向け」はすでに「〜方へ」フォーマットになっており、選択基準が立っている

改善余地:
- 「ライト」の catch「月5回から、HPを育てはじめる」は体言止め+行動提案で、他2プランと文体が揃っていない
- 「ライト」の差別化軸が「回数が少ない」だけでは、選ぶべき人のイメージが立ちにくい

### 採用推奨 → A（全プラン統一）、ただしライトの文言を調整

**採用推奨の最終文面:**

| プラン | catch |
|---|---|
| ライト（¥1,980） | まず月に数回、試しながら続けたい方へ |

| 法人向け（¥14,800） | 複数の事業・担当者でまとめて運用したい方へ |

**理由:**

1. 文体が「〜方へ」で統一され、3プランを横断して読んだ時に選択基準が比較しやすくなる
2. ライト「試しながら続けたい」は「とりあえず安く始めたい」という心理を正直に表現しており、読み手の自己認識と一致しやすい
3. 個人向け「コツコツ育てたい」という言葉が週次の継続感を表し、「HPを育てる」という Insight Cast の提供価値と呼応する
4. 法人向け「事業・担当者」は「プロジェクト」よりも 40-60代の経営者に届く言葉
5. 「週1〜2本のペース」という具体的な頻度は残す。LP構成原則「proof（数字）を置く」の判断基準に合致

## TOP 10 — CastTalkPreview の差別化（BlogPreview との役割分け）

### 現状

`BlogPreview.tsx`:

```
eyebrow: Blog
heading: 最新の記事
補足文: Insight Cast の考え方や、発信にまつわる話を長文の記事で読む。
```

`CastTalkPreview.tsx`:

```
eyebrow: Cast Talk
heading: キャストの対話
補足文: キャスト同士の対話で、ホームページの育て方を学ぶ。
```

2セクション連続で「最新コンテンツ列」に見える。

- BlogPreview: heading「最新の記事」、補足文「考え方や発信にまつわる話を読む」
- CastTalkPreview: heading「キャストの対話」、補足文「ホームページの育て方を学ぶ」

どちらも「読む・学ぶ」系のポジションで差別化が弱い。

---

### 提案候補（heading + 補足文のセット）

**A. 「舞台裏を覗く」ポジション**

```
heading: キャストたちの、舞台裏話
補足文: 取材の合間に、キャストたちが語り合ったこと。HPを育てることについての、本音の対話。
```

**B. 「思想の入り口」ポジション（ブランド寄り）**

```
heading: Insight Cast の思想を、対話で読む
補足文: インタビューするとはどういうことか。価値を引き出すとはどういうことか。キャストたちの言葉で。
```

**C. 「もう一つの入口」ポジション（読みやすさ重視）**

```
heading: キャストが話し合う、発信のこと
補足文: ブログより短く、でも本音が多い。キャスト同士の対話から、発信のヒントを拾う。
```

---

### 採用推奨 → A（「舞台裏を覗く」ポジション）

**理由:**

1. BlogPreview「最新の記事」→「Insight Cast の考え方や発信にまつわる話」という位置づけに対して、CastTalkPreview を「公式記事の裏話 / 本音の対話」として差別化できる。「公式 vs 本音」の対比が分かりやすい
2. 「舞台裏」という言葉は 40-60代の読み手にも親しみやすく（テレビ・雑誌の「舞台裏」という概念がある）、「AIキャストたちが本当に働いている会社」という世界観と自然に接続する
3. 「取材の合間に」という表現が「AIキャストが実際に仕事をしている」という世界観の演出として機能する
4. 候補Bは「思想」という言葉が概念語寄りで、40-60代には少し硬い。候補Cは「ブログより短く」という他セクションとの比較が不自然

**採用推奨の最終文面:**

```
heading: キャストたちの、舞台裏話
補足文: 取材の合間に、キャストたちが語り合ったこと。
        HPを育てることについての、本音の対話。
```

ただし現行の `heading` と `補足文` は JSX 内にハードコードされているため、実装時はその箇所のみ差し替える。eyebrow（Cast Talk）と CTA（Cast Talk をもっと読む）は現状維持。

**修正対象ファイル:** `app/(site)/_components/lp/CastTalkPreview.tsx`
