LP 順序:
**Hero → PainSection → SolutionBridge → HpAnalysisStep → InterviewStep → GrowthStep → OutputExample → EeatSection → CompareCards → PricingPreview → BlogPreview → CastTalkPreview → LpFaqSection → Footer-CTA（PublicFooter promo）**

---

## サマリー（先に結論）

**良い点**
- 階段の骨格は正しい（Pain → Solution → Step → Proof → CTA）
- リズム（cream / surface2 / 暗 / brown）が直近で整理された
- accent オレンジは LP 全体で一貫したサインになっている
- card の bg がほぼ `--surface` で統一され、section bg と階層がつく

**主な弱点**
- Step 章が 3 つあり、その間に Output / EEAT / Compare が挟まる構造で **「Step は何ステップなんだ？」が分かりにくい**
- 同じ proof 系のセクション（EEAT / Compare / Output）が連続して**重い**
- セクション内の eyebrow を全部オレンジに揃えたが、**特定セクションの eyebrow が "場所マーカー" として強すぎる**（後述）
- Footer-CTA と PricingPreview の二度の CTA が連続するように見えるレイアウトで、最後の一押しが薄まっている
- Hero の proof 要素は数字あるが、CompareCards とほぼ同じ「20 分」「¥4,980」「¥83」が再登場 → **proof の繰り返し**

| CTA | ○ | なし（このセクションは煽り、CTA は出さない判断は正しい） |

| リズム | ○ | クリーム bg `#fdf7f0`、暗 → 明の落差で目が休まる |
| eyebrow | ○ | "SOLUTION" がオレンジ |
| heading | ○ | display スケール、左に accent 縦罫 |
| CTA | ○ | なし（次の Step で詳述するため、ここで押させない判断は正しい） |

| 余白 / 送り出し | ○ | リスト 3 項目の最後でフェードアウト。次の Step に自然に渡る |

- 引用ボックスの代わりに **実例 1 つ**（実際の取材ログから引いた "気づき" のサンプル 1 つ）を入れると proof が立つ
- 3 項目（考えなくていい / まとめなくていい / 答えるだけ）は対応関係が美しい。**保ちたい構造**

## 横断的な気づき

1. **Step 章を 3 連続のかたまりとして扱う**のが最大のレバー。今は HpAnalysis / Interview / Growth が独立した 3 セクションに見え、step として認識されにくい
2. **proof セクション（EEAT / Compare / OutputExample）が中盤に固まっている**。一つを後半（Pricing 後）に動かすと proof の効きが変わる可能性。ただし大手術なので別タスク
3. **eyebrow を全部オレンジに揃えた**結果、現状ほぼ全 eyebrow が均等な強さ。代わりに **重要セクションの heading を一段大きく**して "どのセクションが LP の核か" を再度差別化したい
4. **proof が「数字」「写真」に偏っている**。**引用 / 顧客の声** がないので、Phase 3 で実顧客が出てきたら必ず入れる
5. CTA は LP 全体で**最終 CTA に集約**するのが筋。途中の Pricing は "選び方を示す" 役割に絞り、押させたいのは Footer-CTA、という設計が今は良い形。維持
