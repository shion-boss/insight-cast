# 構造先行型取材モード（Structure-First Interview）

## 背景

現状の Insight Cast は「取材 → 記事素材 → 記事完成」の順で動く。場当たり的な取材から記事が生まれる設計で、**事業者の当たり前を引き出す** ことに最適化されている。

一方で、ブログのブランディング水準を上げるためには **5,000〜8,000字のピラー記事** が必要になる。ピラー記事は1回の取材では作れず、論点が網羅されるよう **意図的に取材を設計する必要** がある。

このギャップを埋めるのが、本仕様で提案する「構造先行型取材モード」。

## 概要

記事の **構造（H2/H3 + 各セクションで引き出したい一次情報）を先に定義** し、その構造を埋める形で取材を計画・実施する逆順フロー。

```
従来: 取材 → 素材 → 記事構成 → 記事
新規: 記事構造設計 → 取材プラン生成 → 複数回取材 → 構造への紐付け → 記事
```

## 中核思想を壊さないための設計原則

CLAUDE.md「事業者の当たり前を引き出す」を損なわないことが必須:

1. **構造は事業者に見せない**（あるいは見せ方を選択可能にする）
   - マーケター / AIデザイナー が裏で設計し、事業者は「いつもの取材」を受ける
2. **取材中の脱線・予想外の発言を許容する**
   - 構造に収まらない発言は別カテゴリで保存し、後から構造を更新できる
3. **「構造を埋めるための質問」と「ハッとさせる質問」の両立**
   - キャストへの指示は「このH2を埋めたい」+「事業者の本音を引き出す」の両軸
4. **記事タイプの明示的切り替え**
   - 通常記事モード（既存）/ ピラー記事モード（新規）を切り替え可能に

## 機能要素

### 1. 記事構造エディタ

マーケター が H2/H3 を定義し、各セクションで「引き出したい一次情報」を記述する画面。

```
ピラー記事: AI検索時代に中小企業のHPはどう変わるべきか

  H2-1. AI検索時代の何が新しいのか
    ├─ 引き出したい情報: 検索エンジンが要約する仕組みの変化
    └─ 担当キャスト案: クラウス（業種知識）

  H2-2. 一次情報だけが残る理由
    ├─ 引き出したい情報: 事業者の体験エピソードを最低3件
    └─ 担当キャスト案: ミント（お客様目線で深掘り）

  H2-3. 中小企業が今やるべきこと
    └─ ...
```

### 2. 取材プラン生成

構造から逆算して「どのキャストに何回取材依頼するか」を提案する。

### 3. 複数取材の構造紐付け

同じピラー記事に対して、複数の取材セッション（別日・別キャスト）を紐付けられるようにする。各取材を H2 単位でセクションに割り当てる。

### 4. 充足度可視化

「H2-3 がまだ薄い」など、構造に対してどのセクションがまだ取材で埋まっていないかを可視化。

### 5. 脱線許容ストック

取材で出てきた構造外の発言は、別カテゴリで保存。後から構造を更新するか、別記事の素材に転用できる。

### 6. 記事生成

構造 + 紐付けられた取材素材から、最終的なピラー記事を生成。引用ブロック・要約ボックス・目次を自動生成。

## ターゲット利用者

- **マーケター（社内・外部問わず）**: 顧客のピラー記事戦略を立てる人
- **大手規模の顧客**: 自社で構造を設計できるリテラシーがある事業者（Phase 4 以降）
- 中小企業向けでは、Insight Cast 側のマーケターが代理で構造を作る運用が現実的

## 実装スコープ

### Phase 3 後半（PoC）
- 内部ツール画面で構造エディタを試作
- 既存の取材セッション機能と連携（構造を内部メタデータとして持つ）
- 自社のピラー記事執筆で実証

### Phase 4（顧客向け機能化）
- ピラー記事プラン全体を顧客 UI に開放
- 複数取材の構造紐付け
- 充足度可視化と AI による「次に聞くべきこと」提案

## トレードオフ

- **作成コスト**: 構造エディタ + 複数取材紐付けは UI 複雑度が上がる
- **顧客の認知負荷**: 一般顧客には難しいので、**社内向け機能に留めるか開放するかの判断** が必要
- **取材体験の硬直化リスク**: 「構造を埋める」プレッシャーで取材が機械的になる懸念 → 設計原則で対処

## 関連する既存スキル / 機能

- `interviewer-prompts` skill: 各キャストの質問設計
- `content-authority` skill: 記事の引用価値設計（ピラー記事はこの観点で構造化される）
- `interview-quality` skill: 取材品質
- `blog-theme-analysis` skill: 記事テーマ整理（構造設計の前段で使える）

## 起源

2026-05-07 のディレクター との議論で発案。
ブログ32本の文字数分布を見たところ最大2,159字に留まっており、AI検索引用に有利な5,000-8,000字のピラー記事が一本もない状態。
ピラー記事の必要性が浮かび、その制作には「構造先行型取材」が必要という結論に至った。
