## 背景

これまでの Phase 2 中間マイルストーン（旧定義）は **「知り合い紹介を除いた問い合わせ月2件 + 月500セッション + ブログ累計10本」を1ヶ月維持** だった。
2026-05-07 のユーザーとの議論を経て、以下の論点が浮上した:

1. **ブログ → 流入 → 顧客獲得 のシナリオがそもそも成立しにくい**
   - `insight-cast.jp` は新規ドメインでドメインパワーゼロ
   - ターゲット（HP更新が止まっている AI未経験の中小企業）と、ブログの発信チャネル（AI関連検索層）に**レイヤーズレ**
   - CLAUDE.md「想定リスク: 自社ターゲットと顧客ターゲットのレイヤーが違う」既出
2. **ブログ流入が立たないこと ＝ ツール無価値、ではない**
   - ツール本来の価値は「HPを一次情報で継続的に強くする」こと
   - 顧客HP の効果は **紹介・既存客・ローカル検索でランディングした人の納得感** として現れる部分が大きく、blog SEO 単体では測れない
3. **したがって中間マイルストーンの「月500セッション・月2件問い合わせ」は誤った物差し**
   - 自社の blog SEO 流入を測ることは可能だが、それで Phase 3 移行を判定するのは適切でない

ユーザーの結論: **ブログをブランディング目的に再定義** し、「ブログのブランディング水準」と「ツールの品質水準」の2つのゲートを設ける。両方が揃ったら次フェーズ（マーケティング戦略実行）に入る。

---

## 決定内容

### Phase 2 のゲートを「Gate A: ブログのブランディング水準」「Gate B: ツール品質水準」の2本立てに置き換える

### 旧中間マイルストーン定義は無効化する

「月500セッション + 月2件問い合わせ + ブログ累計10本」の AND条件は撤回する。
旧 decision doc は履歴として残し、冒頭に supersede バナーを置く。

## Gate A: ブログのブランディング水準

### 達成イメージ

紹介・SNS・ローカル検索などで Insight Cast を初めて知った人がブログを読んだ時、
**「この人たちは AI 時代の発信を本気で考えていて、信用できる」** と感じる状態。

### 達成条件

| 観点 | 条件 |
|---|---|
| 累計本数 | 30本以上（**現状32本で達成済み**） |
| トピック網羅 | 5系統がそれぞれ4本以上揃う ①AI検索時代の発信観 ②一次情報・引用価値の方法論 ③動物キャラ・インタビュアー型の意図 ④中小企業のHP更新リアル ⑤自社プロセス開示（メタ記事） |
| 質的水準 | `content-authority` skill の引用価値・E-E-A-T 基準を全記事で通過。マーケター + レビュアーで全記事レビュー済み |
| 構造 | カテゴリ・タグ・関連記事・各記事末尾CTA・内部リンクが整備されている。`/about` `/philosophy` と blog の世界観が一本に繋がっている |
| 外形 | ブログ TOP に来た時に「読み物として整っている」見た目（カテゴリ導線・サムネ・著者表示） |

### 判定方法（3層構成）

- **マーケター**: 一次判定 — 5系統トピック網羅・引用価値・コピー水準
- **レビュアー**: 二次チェック — 世界観整合・E-E-A-T・構造
- **ディレクター**: 最終承認 — Phase 移行判断として起票

3者が **「初見の人に見せて恥ずかしくない」と一致** で判定（質的判定優先）。
判定セッションを Phase 2 終盤で1回開く。

### Gate A 着手時の最初の作業

- 32本のトピック分類棚卸し（5系統への割当・不足系統の特定）
- ブログ TOP の構造監査（マーケター主導）
- 質チェック対象記事の優先順位付け

## Gate B: ツール品質水準

### 達成イメージ

第三者（テストユーザー）が運営の手助けなしで
**登録 → 調査 → インタビュー → 記事生成 → 投稿** まで完走できる。途中で詰まらず問い合わせも来ない。

### 達成条件

| 観点 | 条件 |
|---|---|
| 機能完走性 | テストユーザー3人が手助けなしで完走（取材1回 + 記事1本投稿）。完走率 100% |
| 9軸品質サイクル | 4週連続で全軸 A〜B+。Blocker / Should Fix のゼロ運転 |
| AIキャスト評価 | 全キャラ（ミント・クラウス・レイン・ハル・モグロ・コッコ）が `docs/review-log/ai-cast-evaluation.md` の目標スコアを **3件連続**で達成 |
| パフォーマンス | LP First Load JS 220kB前後を維持。Lighthouse Performance 90+ |
| 安定稼働 | 月次インシデント0件・手動介入0件が **2ヶ月連続** |
| コスト | AI APIコストが ファイナンス の想定モード内（1.2万 / 2.4万 / 4万）で安定 |
| モバイル | 主要画面のモバイル Should Fix 残ゼロ |

### 判定方法

レビュアー ＋ ファイナンス ＋ オペレーター が一致して「これなら売れる」と判断。

### テストユーザー実行のタイミング

**Gate B の他項目（9軸4週・キャスト評価・安定稼働）が揃ってから**実施。
手助けなし完走の体験品質を下げないため、土台ができてから入れる。

## 両ゲート到達時の次フェーズ: マーケティング戦略実行

ゲート到達時点で揃っている素材:
- 自社HP（ブログ32本以上 + LP + about + philosophy）= 営業資料
- 動くツール = デモ可能
- AIキャスト評価データ = 効果根拠
- ファイナンス の運用コスト実績 = 価格根拠

### 戦略骨子（ゲート到達時にマーケター主導で詳細化、いまは設計図）

#### 1. 獲得チャネルを Organic 一本から外す

- **紹介経路（知人・既存ネットワーク）から最初の3件**を取る設計
- 商工会 / 地域SNSグループ / 業界向けメディア寄稿
- SNS（Facebook / Instagram）・Note クロスポストで認知
- 業種を絞らずに進めるが、最初の3件は紹介経路で取り、業種偏りを許容する

#### 2. HP を「証拠」として使う

- 紹介された人 / SNS 経由で来た人が HP に着地した時に、**ブログ + LP + about の3点で説得力**を作る
- つまり Gate A はこの戦略の前提条件

#### 3. デモ・営業資料の整備

- スクリーンキャスト（取材→記事生成までのフルフロー）
- 価格根拠の提示（HP強化のサブスクとしての説明）
- トライアル設計（無料プランで取材2回 → 体験 → サブスク）

#### 4. KPIツリー

- サブスク5件達成までの逆算
- 紹介→トライアル→契約のCVR目標
- 月次の確認指標を `ops/milestone-tracker.md` に組み込む

#### 5. 行き詰まり判定の更新

- 旧定義の「Organic 流入失敗」型ではなく、「**紹介経路でも届かない場合のターゲットレイヤーズレ**」に更新
- 紹介経由でトライアル0件が3ヶ月続く / トライアル後の継続意向が0% など、紹介経路前提の判定基準に書き換える
